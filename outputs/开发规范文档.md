# 开发规范文档

## 1. 项目概述

本项目旨在开发一个类似ChatPDF的智能文档处理系统，支持多源文档输入（PDF、Word、图片、网页），通过多模态解析和智能提取，构建知识图谱和向量库，实现基于混合检索的智能问答功能。

### 1.1 核心功能

- 多源文档输入与解析（PDF、Word、图片、网页）
- 多模态解析（版面分析、表格、公式、图片）
- 智能提取（实体、关系、属性结构化）
- 知识图谱存储（Neo4j）
- 向量库存储（Milvus）
- 混合检索与AI问答（LangChain）
- 服务层（FastAPI）
- 前端交互（React）
- 用户认证与权限管理

### 1.2 参考产品

参考ChatPDF.com的核心功能：
- 文档智能问答
- 自动摘要生成
- 多文件聊天
- 多语言支持
- 引用来源功能
- 多种文件格式支持

## 3. 系统架构

### 3.1 架构图

```
多源文档入口 → MinerU多模态解析 → LangExtract智能提取 → 双存储（Neo4j知识图谱 + Milvus向量库） → LangChain混合检索+AI → FastAPI服务层 → React前端
```

### 3.2 数据流向

1. **多源文档输入**：用户上传PDF、Word、图片、网页等多种格式的文档
2. **MinerU多模态解析**：对文档进行版面分析，识别表格、公式、图片等元素
3. **LangExtract智能提取**：提取文档中的实体、关系、属性，进行结构化处理
4. **双存储**：
   - Neo4j：存储实体-关系-属性的知识图谱
   - Milvus：存储文档嵌入向量，支持相似性搜索
5. **LangChain混合检索+AI**：结合图谱检索和向量检索，通过大语言模型生成答案
6. **FastAPI服务层**：提供API接口，处理请求路由、鉴权、中间件等
7. **React前端**：提供用户交互界面，支持文档上传、聊天对话、结果展示等

### 4.3 数据模型

#### 4.3.1 知识图谱模型

- **实体**：文档、章节、段落、表格、图片、公式、人物、组织、地点、概念等
- **关系**：包含、引用、描述、属于等
- **属性**：标题、内容、位置、类型、创建时间等

#### 4.3.2 向量库模型

- **文档片段**：将文档分割成合适的片段
- **嵌入向量**：使用预训练模型生成片段的向量表示（OpenAI text-embedding-3-small, 1536维）
- **元数据**：包含片段来源、位置、类型等信息

#### 4.3.3 关系型数据库模型

- **用户表**：id, email, name, password_hash, created_at
- **文档表**：id, user_id, folder_id, name, type, size, file_path, processing_status, created_at
- **聊天会话表**：id, user_id, title, created_at
- **聊天消息表**：id, session_id, role, content, references, created_at
- **文件夹表**：id, user_id, parent_id, name, created_at

## 5. 开发流程和规范

### 5.1 开发环境

- **前端**：Node.js 18+, npm/yarn, React 18+, TypeScript, Vite
- **后端**：Python 3.11+, FastAPI, LangChain, Celery
- **数据库**：PostgreSQL 15+, Neo4j 5.0+, Milvus 2.0+, Redis 7.0+
- **开发工具**：VS Code, Git
- **容器化**：Docker, Docker Compose

### 5.2 代码规范

- **前端**：ESLint, Prettier, TypeScript（严格模式）
- **后端**：Flake8, Black, MyPy
- **提交规范**：Conventional Commits
- **分支管理**：Git Flow

### 5.3 测试策略

- **单元测试**：pytest (后端), Vitest (前端)
- **集成测试**：FastAPI TestClient
- **端到端测试**：Cypress
- **测试覆盖率**：保持80%以上

### 5.4 部署策略

- **前端**：Vercel（推荐）或自建Nginx静态服务器
- **后端**：Docker + Kubernetes
- **数据库**：PostgreSQL自建, Neo4j Aura或自建, Milvus Cloud或自建, Redis自建

### 5.5 环境变量管理

- 所有配置通过环境变量注入，禁止硬编码
- 后端使用`.env`文件 + Pydantic `BaseSettings`加载
- 前端使用`.env`文件 + `import.meta.env`访问（`VITE_`前缀）
- `.env.example`提交到Git，`.env`加入`.gitignore`
- 敏感信息（API Key、数据库密码等）禁止提交到代码仓库
- 生产环境使用密钥管理服务（如AWS Secrets Manager）

### 5.6 Code Review流程

1. 开发者在feature分支完成开发并自测通过
2. 提交Pull Request到develop分支
3. 至少1位Reviewers审核代码
4. CI流水线自动运行（lint、typecheck、test）
5. Reviewer确认代码质量、规范合规、测试覆盖
6. 审核通过后合并，删除feature分支

Review重点：
- 代码是否符合项目规范（命名、格式、类型）
- 是否有明显的安全漏洞
- 测试是否覆盖核心逻辑
- 是否有性能问题（N+1查询、内存泄漏等）

## 6. 关键技术实现

### 6.1 多模态文档解析

使用MinerU进行文档解析，处理不同类型的文档元素：
- 文本内容：直接提取
- 表格：转换为结构化数据
- 公式：识别和提取
- 图片：OCR识别文字内容

### 6.2 智能信息提取

使用LangExtract结合大语言模型，提取文档中的结构化信息：
- 实体识别：人物、组织、地点、概念等
- 关系抽取：实体之间的关联关系
- 属性提取：实体的特征和属性

### 6.3 混合检索策略

使用LangChain实现混合检索：
- **图谱检索**：基于Neo4j的图查询，获取相关实体和关系
- **向量检索**：基于Milvus的相似性搜索，获取相关文档片段
- **重排序**：结合两者结果，优化回答质量

### 6.4 知识图谱构建

使用Neo4j构建知识图谱：
- 设计合理的节点和关系模型
- 实现高效的图查询算法
- 支持增量更新和维护

### 6.5 向量库优化

使用Milvus优化向量存储和检索：
- 选择合适的嵌入模型
- 优化索引参数
- 实现高效的向量更新策略

## 11. 分支管理

本项目使用Git Flow分支管理策略，具体分支规划如下：

- **main**：主分支，用于发布生产版本
- **develop**：开发分支，用于集成开发功能
- **feature/**：功能分支，用于开发新功能（如`feature/user-auth`、`feature/chat-websocket`）
- **hotfix/**：热修复分支，用于修复生产环境问题
- **release/**：发布分支，用于版本发布前的测试和修复

### 11.1 分支命名规范

```
feature/<模块>-<简短描述>    # 如 feature/auth-jwt-login
hotfix/<模块>-<简短描述>     # 如 hotfix/chat-ws-reconnect
release/<版本号>             # 如 release/v1.0.0
```

### 11.2 提交信息规范

使用Conventional Commits格式：

```
<type>(<scope>): <subject>

<body>

<footer>
```

type类型：
- `feat`: 新功能
- `fix`: 修复Bug
- `docs`: 文档变更
- `style`: 代码格式（不影响功能）
- `refactor`: 重构
- `test`: 测试
- `chore`: 构建/工具变更

示例：
```
feat(auth): 实现JWT登录和Token刷新

- 添加登录API端点
- 添加Token刷新逻辑
- 添加认证中间件

Closes #12
```

**部署流水线**（合并到main触发）：
1. 执行PR检查流水线所有步骤
2. 构建Docker镜像
3. 推送到镜像仓库
4. 部署到生产环境
5. 运行冒烟测试
6. 发送部署通知
